# 排障与复现

## 启动或配置失败

在仓库根目录使用虚拟环境解释器，先执行 `python -m pip check`。配置错误返回CLI退出2/API422，检查profile、题号、策略、数量与超时；case-count必须覆盖所有选中策略，线程数1–16。
profile ID是本地题意，problem-id是远端真实题号，不可混用。真OJ使用seed返回的题号。

## 数据库被占用或重启后任务中断

同一数据库只能有一个执行进程；停止原Web后再用CLI，或传独立 `--db runtime/ci.db`。不要删除运行锁来绕过活跃进程。
进程异常退出后获得锁的新进程会把遗留活动任务标记INTERRUPTED，保留历史；重新执行应创建新任务并重新提供凭据，不重放旧任务。
升级前停止平台并备份数据库与整个报告根目录，避免SQLite的WAL文件遗漏；已有数据不要用清库解决问题。

## 登录或判题失败

检查base-url和登录结果；CLI密码只通过OJ_PASSWORD传递。Mock演示账号仅能用于Mock，不能用于真实OJ。
HTTP200也可能是业务拒绝；在任务详情查看kind、HTTP码、业务码和实际判题。负向测试出现预期401可为PASSED，不能只看HTTP状态判断平台失败。
超时/协议异常是ERROR，不能用预期ERROR通配；提交POST无自动重试。先核对服务日志和任务源码哈希，再决定是否创建新任务。

## 取消迟迟未完成

CANCEL_REQUESTED表示停止新提交并等待在途请求返回或到期，不是立刻杀死远端程序。查看request_timeout及remote_execution_may_continue，不把页面状态当作远端进程结束证明。

## 报告打不开

404检查文件是否缺失；422检查报告哈希和路径边界。数据库中报告索引与文件必须来自同一次任务，不手工修改报告让哈希检查通过。
迁移时同时带走数据库和原报告目录。强制终止可能留下未登记文件，应先保留并核对索引，不能把它当作已登记成功报告。
下载CI制品到短目录，或用Windows长路径方式读取；深层UUID报告路径可能超过普通Win32路径限制。

## Docker启动或真实E2E失败

确认Docker Desktop Linux引擎运行。Mock演示与真实E2E是两套Compose，不把配置指向共享服务。
真实环境必须显式 `--env-file .env.e2e -f compose.e2e.yaml`；只执行 `config --quiet`，普通config会展开密码。
使用 [e2e环境检查](e2e.md)核验网络、容器、SHA、数据库和部署标记，再运行测试；端口18090被占用应查明原因，不能换到未知服务。
数据库卷与.env.e2e必须配套保留；不能保留旧卷却重新生成密码。升级固定SUT时按e2e.md使用新部署ID和新卷，旧卷保留。
构建默认Debian源慢时可使用文档允许的SJTU镜像参数；不关闭TLS或APT签名校验。

## CI失败但有报告

这是预期行为：报告和上传使用always()，后续成功不抵消pytest失败。先看JUnit和失败步骤，再核对artifact内manifest、platform_sha和哈希。
依赖安装失败、零测试或缺少报告必须保持失败，不能创建空HTML或跳过真实E2E冒充绿色。
真实SUT当前公开可匿名检出；若访问失败，作业应明确失败。GitHub制品14天后可能过期，可使用本地下载副本，或对所需提交重新运行并记录新run。
仅上传ci-e2e-artifacts中的脱敏文本；不要上传.env.e2e、SQLite、config展开输出或原始凭据。
